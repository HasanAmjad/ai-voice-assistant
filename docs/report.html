Project Description

Goal. Build a production-grade voice-to-intent pipeline that converts spoken banking customer queries into classified intents and synthesised voice replies. Domain: customer-support automation. Use case: an IVR-style agent that auto-handles confident calls and hands off uncertain ones to humans.

Dataset. BANKING77 from HuggingFace (mteb/banking77): 13,069 real customer queries across 77 fine-grained banking intents (e.g. card_blocked, transfer_not_received_by_recipient, exchange_rate). Text-only, so we synthesise corresponding audio with gTTS, then feed it back through Whisper to recover transcripts — exercising the full speech-to-text leg of a real call-centre stack.

Why PostgreSQL. Relational fit (clear FK relationships, joins for evaluation queries), GX integrates natively via dataframe extraction, SQLAlchemy ORM gives us migration safety, and Postgres handles 13k rows trivially while remaining production-realistic.

Production-grade Extension: Model Deployment with Drift & Threshold Policy

Of the five advanced extensions, we implemented #4 Production-grade Model Deployment. Concretely:

  • Versioning: models saved as model_v{YYYYMMDD_HHMMSS}.pkl; model_runs table tracks accuracy, F1, drift, and SHA-256 data hash per run; latest_model.pkl + latest_model.txt form a stable serving alias.
  • Drift detection (two layers): training-vs-test JS divergence at evaluate time, and live rolling-window divergence over the most recent 100 vs prior 100 predictions via GET /drift, with top-mover intents surfaced.
  • Confidence-gated routing: CONFIDENCE_THRESHOLD=0.4, justified by a sweep over [0.10–0.90] on the test set (docs/threshold_sweep.png): at 0.4 we escalate 23.3% of calls, the auto-handled subset is 95.9% precise, and only 3.2% of all calls receive a confidently-wrong canned reply. Below-threshold predictions get a synthesised "redirecting to an agent" voice handoff.
  • Operational hygiene: idempotent schema migrations on API startup, disk-cached gTTS audio (95 entries, hot reload across restarts), pre-warmer thread fills the cache in the background, dashboard surfaces recent calls + drift + model version.
